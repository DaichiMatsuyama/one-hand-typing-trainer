# 練習記録の受け取り(Google Apps Script)の設定手順

アプリの「初回コード入力」と、練習記録のGoogleスプレッドシートへの保存に使う。所要時間は5〜10分。

## 仕組み

- アプリは、ホーム画面から開かれ、かつアクセスコードを一度入力した端末だけで使える。
- コードの確認と練習記録の受け取りは、このスクリプト(`Code.gs`)が行う。コードはスクリプトの設定にだけ保存され、公開リポジトリには載らない。
- 練習記録は、1問クリアごとに1行、スプレッドシートの `records` シートに追記される。再送時はシートの記録IDを照合し、既存IDと同じ送信内の重複IDを除く。
- 1回の練習が結果画面へ進んだときは、runごとに1行、`runs` シートへ追記される。`records` と同じく履歴IDで重複を除く。「練習設定へ戻る」では送信しない。
- 形式が不正な記録はその記録だけを読み飛ばし、ほかの正常な記録は保存する。

## action一覧

| action | 用途 | 保存・参照先 |
|---|---|---|
| `verify` | アクセスコードの確認 | シート操作なし |
| `log` | 1問クリアごとの記録(最大50件) | `records` へ追記 |
| `log_run` | runごとの記録(最大20件) | `runs` へ追記 |
| `stats` | 通常利用者本人の振り返り集計 | `records` のみ参照 |
| `admin_devices` / `admin_stats` | 管理者用の端末一覧・振り返り集計 | `records` のみ参照 |

## 手順

1. Googleドライブで、新しいスプレッドシートを作る(名前は例: `タイピング練習記録`)。
2. メニューの「拡張機能」→「Apps Script」を開く。
3. 最初からある `コード.gs` の中身をすべて消し、このフォルダの `Code.gs` の内容を貼り付けて保存する。
4. 左の「プロジェクトの設定」(歯車)→ 一番下の「スクリプト プロパティ」→「スクリプト プロパティを追加」で、次を追加して保存する。
   - プロパティ: `ACCESS_CODE`
   - 値: 友人に教えるアクセスコード(**8文字以上のランダムな英数字**にする。短いと総当たりされやすい)
5. 右上の「デプロイ」→「新しいデプロイ」→ 種類の歯車で「ウェブアプリ」を選び、次のとおり設定して「デプロイ」する。
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**
   - 初回は、Googleアカウントの承認画面が出る(スプレッドシートへの書き込みの許可)。
6. 表示された「ウェブアプリのURL」(`https://script.google.com/macros/s/.../exec`)をコピーする。
7. そのURLを、アプリの `src/remoteConfig.js` の `DEFAULT_ENDPOINT` に設定してデプロイする(Claude Codeに「URLはこれ」と渡せばよい)。

URLを設定するまで、アプリは今までどおり誰でも制限なく使える(記録も送られない)。

## 振り返り画面(成績の表示)と管理者用コード

アプリを縦向きにすると、「振り返り」画面が出る(今日のまとめ、キーごとのミスのヒートマップ、日ごとの練習時間、正答率の推移、よくある押し間違い)。集計はこのスクリプトが行い、スマホには集計結果だけを返す。

- **友人(練習する人)**は、自分の端末の記録だけが見える。
- **マギさん(管理者)**は、振り返り画面の見出し「振り返り」を**約5秒長押し**すると(画面には何も表示されない隠しの入口)、管理者用コードの入力欄が出る。コードを入れると、端末の一覧(最終練習日・問題数・練習時間つき)から、見たい端末を選べる。入力欄の「閉じる」で隠せる。
- 管理者用コードは、アクセスコードとは**別の値**にする(友人には教えない)。スクリプトプロパティ `ADMIN_CODE` に保存する。未設定の間は、管理者表示は使えない(通常の振り返りは使える)。
- 管理者用コードは、入力した端末に保存され、次回から入力不要になる(コードが違ったら保存を消す)。

### 振り返り機能を追加するとき(スクリプトの更新)

1. Apps Scriptの画面で、`コード.gs` の中身をすべて、最新の `Code.gs` に置き換えて保存する。
2. 「プロジェクトの設定」→「スクリプト プロパティ」に、`ADMIN_CODE`(管理者用コード、**8文字以上のランダムな英数字**、アクセスコードとは別の値)を追加して保存する。
3. 「デプロイ」→「デプロイを管理」→ 鉛筆アイコン →「バージョン: **新バージョン**」→「デプロイ」。URLは変わらない。

## `runs` シートに列を追加したとき(ホームポジション確認の4列)

`runs` シートの末尾に `hpSuccessCount` `hpSkipCount` `hpAvgReturnMs` `hpMinReturnMs` の4列が加わった(合計28列)。**先にこのスクリプトを更新(新バージョンでデプロイ)してから**、アプリを公開する。旧版のスクリプトのままだと、アプリが送る新しい項目は無視され、復帰時間が記録されない。

- **既存の `runs` シートは手で直さなくてよい。** 1行目が旧24列の見出しと完全に一致していれば、最初の `log_run` を受け取ったときに、スクリプトがロックの中で25〜28列目の見出しだけを書き足してから追記する(既存の行は変わらず、新しい4列は空欄のまま)。2回目以降は何もしない。
- 見出しが新28列と完全に一致するときは、そのまま追記する。
- 上のどちらでもない(見出しを書き換えた、列を足した・消した、並びを変えたなど)ときは、何も書き込まず `sheet_header_mismatch` を返す。この場合、アプリはその記録を端末に残して再送を続ける。`runs` シートの1行目を旧24列(または新28列)の見出しに戻せば、次の送信から再び保存される。
- 新4項目は、確認なし(`homePosition` が `false`)の記録では省略してよい(旧版のアプリの記録も受け付け、空欄で保存する)。値があるときは、回数が0〜100000の整数、時間が0〜86400000の整数または空欄。確認なしの記録で回数が1以上、時間がある記録は不正として断る。
- 確認あり(`true`)の記録は、成功回数・スキップ回数が必須で、成功0回なら平均・最短は空欄、1回以上なら平均・最短が必須。さらに、最短 <= 平均、成功+スキップ <= 完了問題数、平均 <= 総経過時間、平均×成功 <= 総経過時間+1000ms を満たさない記録は、その記録だけを断る。
- `runs` シートの列数(グリッド)が足りないときは、書き込み前に列を足す(新規作成のシートは既定26列のため)。移行・追記のあと、ロックを手放す前に `SpreadsheetApp.flush()` で反映を確定する。
- **注意(戻すとき):** ヘッダーを移行したあとにスクリプトを旧版へ戻すと、旧版は24列固定のため `sheet_header_mismatch` になり、`runs` の記録が止まる。戻す場合は、先に `runs` シートの25〜28列目(見出しとデータ)を削除してから戻す。

## 注意: ランタイム

`Code.gs` は `Set` を使うため、Apps Scriptの**ランタイムがV8**である必要がある(新しく作ったプロジェクトの既定)。「プロジェクトの設定」の「Chrome V8 ランタイムを有効にする」がオンか、確認する。

## 動作確認

- Safariのタブでアプリを開くと、「ホーム画面に追加してください」の案内だけが出る。
- ホーム画面から開くと、コード入力画面が出る。正しいコードで入力すると、練習画面になる。
- 1問クリアすると、`records` シートに1行増える。
- 練習メニューから「練習を終了」して結果画面へ進むと、`runs` シートに1行増える。
- 旧24列の `runs` シートがあるときは、最初の記録を受け取ったときに1行目の右端へ4列の見出し(`hpSuccessCount` など)が足される。
- 縦向きにすると、振り返り画面が出る。見出し「振り返り」を約5秒長押しして、管理者用コードを入れると端末一覧が出る。

## 総当たり対策(ロック)

最初の失敗から始まる固定5分間に、アクセスコードまたは管理者コードの間違いが30回に達すると、その窓が終わるまでは**正しいコードでも**確認・記録が断られる(`locked`)。失敗のたびに5分間が延びることはなく、コード確認に成功すると失敗回数はリセットされる(管理者操作は両方のコードが正しいときに成功扱い)。誰かが偽のコードを連打すると、友人が一時的に入力できなくなることがある。そのときは最初の失敗から5分ほど待ってやり直す。

## コードを変更するとき

`ACCESS_CODE` を変えると、**新しい端末の入力と、これからの記録の送信は、新しいコードでないと断られる**。すでに入力済みの端末は、アプリ自体は使い続けられるが、記録は送られなくなる(練習は止まらない)。

スクリプトを書き換えたときは、「デプロイ」→「デプロイを管理」→ 鉛筆アイコン →「バージョン: 新バージョン」にして更新する(URLは変わらない)。

## `records` シート(1問ごと)に記録される項目

| 列 | 内容 |
|---|---|
| receivedAt | 受信日時 |
| id | 記録のID(再送の重複排除用) |
| ts | 端末側の日時 |
| deviceId | 端末ごとのランダムID(個人は特定しない) |
| hand / level / includeSymbols / layout | 手・レベル・記号の有無・配列 |
| question | 出題された文字列 |
| durationMs | 所要時間(ミリ秒) |
| attempts / mistakes | タップ数・ミス数 |
| wrong | 押し間違い `[正しいキー, 押したキー]` の一覧(JSON) |

位置情報や氏名などは送らない。

## `runs` シート(runごと)に記録される項目

| 列 | 内容 |
|---|---|
| receivedAt / id / ts / deviceId | 受信日時・履歴と共通の重複排除ID・端末側日時・匿名の端末ID |
| mode / hand / level / includeSymbols / layout | 練習モードと設定 |
| targetCount / timeLimitSec | タイムアタックの問題数・制限時間。対象外のモードでは空欄 |
| homePosition | 「ホームポジション確認」をONで走ったか(`true` / `false`) |
| endedBy | `completed` / `timeUp` / `ended` の終了理由 |
| activeMs / inputMs | runの総経過時間・問題入力時間(停止中の時間を除く) |
| completedQuestions / correctCount / mistakes / attempts | 完了問題数・正しい入力数・ミス数・入力回数 |
| accuracy / kpm / menuOpenCount | 正答率・KPM・メニューを開いた回数 |
| rankVersion | 現段階では空欄。ランク追加時に使用 |
| appVersion | アプリのビルド識別子 |
| hpSuccessCount / hpSkipCount | ホームポジション確認の成功回数・スキップ回数。確認なしのrunは `0`。旧版のアプリの記録は空欄 |
| hpAvgReturnMs / hpMinReturnMs | 復帰時間(問題クリアから4本そろうまで。メニューなどの停止中を除く)の平均・最短(ミリ秒、整数)。成功が0回、確認なし、旧版のアプリの記録は空欄 |

`stats` / `admin_*` は現在も `records` だけを読み、`runs` は振り返り集計へ含めない。位置情報、氏名、端末機種などは送らない。

## 見るときのヒント

- 日ごとの練習時間は、ピボットテーブルで `ts` の日付ごとに `durationMs` を合計する。
- 苦手なキーは、`wrong` 列の正しいキー(1つ目)を集計する。

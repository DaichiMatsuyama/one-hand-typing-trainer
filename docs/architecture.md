# アーキテクチャ

> ※一部は古い。2026-11-03以降の決定は `docs/decisions.md`(決定事項1〜)が優先。

## 初期構成
- フロントエンド: Vue 3 + Vite。
- 公開: GitHub Pages (HTTPSの静的ホスティング)。GitHub Actionsによるビルド・デプロイを推奨。
- 保存: localStorage（初期版）。消去やブラウザ制限で履歴が失われる可能性を許容。
- バックエンド、DB、Dockerは初期版では不要。

## モジュール案
- `keyboardLayouts`: 配列、段オフセット、担当指、ホームポジション。
- `questionBank`: 左右・レベルごとの問題データと出題バリデーション。
- `practiceSession`: 出題、入力、正誤、クリア、統計。
- `storage`: 設定とローカル練習履歴。
- `components`: KeyboardView / PromptView / LevelSelector / ResultView。

## GitHub Pages注意点
- Viteの`base`をリポジトリ名に合わせて設定する（プロジェクトサイトの場合）。
- 静的ファイルのパス、SPAのルーティング方式、キャッシュ更新を検証する。
- 公開リポジトリに秘密情報を置かない。クライアントに埋め込んだキーやトークンは秘密にならない。

## 管理者向け集計（後続）
- GAS Webアプリに起動・練習完了イベントを送信し、Google Sheetsに保存する案。
- ログイン不要とする場合の識別方法・なりすまし・不正送信・重複送信対策を別途設計する。GASのURL秘匿のみを認証とみなさない。
- データ最小化: 起動日時、練習時間、レベル、正答率、苦手キーなど必要な情報のみ。位置情報は不要。
- 利用者に送信項目・目的・閲覧者を説明し、同意後に有効化。利用停止・記録削除手段も検討。
- 通信失敗時は練習自体を止めない。必要ならローカルキューから再送。

## 検証
- iPhone Safari（横向き、縦向き）を実機で確認。
- Chrome等のPCブラウザでロジックのテスト。
- 問題辞書のキー範囲チェック、誤入力、最終文字、左右切替、レベル切替、リセット、保存復元を自動テスト。

# 決定事項(引き継ぎ資料への上書き)

引き継ぎ資料(README / requirements / screen-design / architecture)と食い違う場合は、本ファイルを優先する。

## 2026-11-03 マギさん決定

1. **リポジトリ**: `one-hand-typing-trainer`、**Public** + GitHub Pages(GitHub Actionsでビルド・デプロイ)。Privateは無料プランでPages不可のため。公開前提なので秘密情報・個人データ・実利用ログは一切置かない。
2. **キー範囲**: 記号キーも出題に含める。MVPで対象とする記号は右手の `; , . /` のみ(JIS/USで物理位置が同じため)。左手は英字15キー(Q W E R T / A S D F G / Z X C V B)。右手は英字(Y U I O P / H J K L / N M)+ `; , . /`。数字行・Shift・その他の記号(`-` `@` `:` `[` `]` `'` など)はMVPでは扱わない。
3. **JIS/US**: 利用者のPCはJIS。ただし将来US配列にも対応したい。
   - 配列データに `layoutVariant`(`jis` | `us`)の概念を持たせ、JIS/USで差が出るキーを後から追加しやすい構造にする。
   - MVPは `jis` と `us` で差のないキーのみ(上記範囲)なので、見た目と出題は同一でよい。設定UIで切り替えさせる必要はない(データ構造だけ用意)。
   - 記号キーの追加拡張時は、差分キー(JIS: `:` `@` `[` `]` 等 / US: `'` `[` `]` 等)を `layoutVariant` ごとに定義する。

## 実装方針メモ

- 出題は配列データから自動生成し、全問題が選択中の手のキーだけで構成されることをテストで保証する。
- 記号を含む出題は初心者の負担になるため、Lv.1〜3それぞれで英字のみの問題を主体とし、記号は「記号を含める」設定(既定はOFFまたは低頻度)で制御する想定。出題比率は未確定のためプロトタイプで調整できるよう定数化する。
- 大文字小文字は区別しない。Shiftは扱わない。
- 画面入力はタップのみ(物理キーボード入力は対象外)。

## 2026-11-03 実機フィードバックによる追加決定

以下は上記「キー範囲」「JIS/US」のMVP決定を拡張し、食い違う箇所を上書きする。

1. **クリア後の進行**: 最終キーの正解後はクリア表示を600ms保持し、自動で次の問題へ進む。「次の問題」ボタンと設定による切替は設けない。待機中は入力を受け付けず、やり直し・手・レベル・記号設定の変更時は予約を取り消す。
2. **JIS右手の6列目**: JIS配列の右手だけ、上段 `@`、ホーム段 `:`、下段 `_` を各行の右端へ追加する。3キーとも右手小指の記号キーとする。JIS右手は各段6列、最大幅は下段の `offset 0.75 + 6列 = 6.75ピッチ` となる。
3. **USの6列目は未対応**: US配列では同じ物理位置の記号がJISと異なるため、今回は従来の5列（最大5.75ピッチ）を維持する。USの6列目は別途配列定義を決めてから対応する。
4. **`_` の扱い**: JISの `_` は「ろ」キーのShift入力で、Shiftなしは `\` になる。本アプリはShift非対応だが、`_` はキー位置を覚えるための表記として配置する。`?`（Shift + `/`）は今回の対象外とし、次の段階で検討する。
5. **幅と凡例**: キーピッチの幅基準は、選択中の手・配列における各行の `offset + 列数` の最大値から算出する。右手の凡例はキーを縮小させず、下段左側の0.75ピッチの空きへ縦に配置する。そこにも収まらない極小表示では凡例を非表示にしてよい。
